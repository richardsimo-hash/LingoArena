# STT FUNCTION_INVOCATION_FAILED follow-up

The deployed error `FUNCTION_INVOCATION_FAILED` is generated by the serverless platform and is different from a structured JSON error returned by the STT handler. It can indicate a startup/module-loading failure, an invocation crash, or an environment/runtime issue. The client-side message alone does not identify the cause.

This patch makes `api/stt.ts` self-contained (no shared rate-limit import), explicitly imports Node's `Buffer`, validates JSON/body and audio size before provider work, and returns structured errors for network, provider, and handler failures. It logs bounded error detail without logging audio bytes or the API key.

After deployment, test `POST /api/stt` again. If Vercel still returns the platform-generated `FUNCTION_INVOCATION_FAILED` rather than the route's JSON error, open Vercel → Project → Logs → Functions, select the `/api/stt` invocation at the matching timestamp, and inspect the first exception/stack trace. That stack trace is required to distinguish build/runtime failure from request/provider failure.

This patch has not been deployed or tested against the live Vercel project. It does not claim to prove the original crash cause.
